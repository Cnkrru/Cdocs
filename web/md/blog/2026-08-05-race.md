---
title: "Bug：多 locale 并行渲染时 pages[i].html 竞态导致中文页面显示英文内容"
date: "2026-08-05"
tags: ["bug"]
---

## 现象

`zh-CN` locale 的文档页面显示英文正文——例如 `/v2/zh-CN/getting-started/intro.html` 的 `<h1>` 是 "Introduction" 而非 "介绍"。

## 排查

### 1. 疑点：源文件加载

`render_doc_pages` 按 locale 选择源文件：

```
zh-CN: intro.md（中文） ← 正确
en:    intro.en.md（英文） ← 正确
```

加 debug 确认源文件选择无误：`loc=zh-CN src=intro.md`。但输出仍是英文。

### 2. 真凶：`pages[i].html` 竞态

`render_doc_pages` 的内容渲染阶段直接写 `pages[i].html`：

```cpp
// content 阶段（并行——两 locale 同时跑）
pages[i].html = render_doc_body(md, rc.curLocale == "en");

// emit 阶段（并行）
ctx.body = pages[i].html;
```

`pages` 是 `BuildContext` 的共享成员。多 locale 并行渲染时：

```
Thread zh-CN: pages[i].html = 中文内容
Thread en:    pages[i].html = 英文内容  ← 覆盖了 zh-CN 的写入

Thread zh-CN: ctx.body = pages[i].html  ← 读到英文！
```

原先串行渲染时 zh-CN → en 顺序执行，zh-CN 写盘后 en 才覆盖，不影响已输出的文件。改为并行后出现竞态。

### 修复

```cpp
// 改为 locale 局部的 bodyStore 数组
std::vector<std::string> bodyStore(pages.size());
bodyStore[i] = toc.html;  // content 阶段写入局部数组
ctx.body = bodyStore[i];   // emit 阶段读取局部数组
```

### 教训

**"改串行为并行时，必须审计所有共享写操作。"** 原先能跑不代表线程安全。`pages[i]` 的 `html`、`title`、`desc`、`lastmod`、`aliases` 等多个字段曾被 content 阶段修改——其中 `html` 和 `title` 是多线程竞态的。修复后 `bodyStore` 局部化杜绝了覆盖。
