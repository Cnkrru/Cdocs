---
title: "Bug: Race Condition in Multi-Locale Parallel Rendering Causes Wrong Language Content"
date: "2026-08-05"
tags: ["bug"]
---

## Symptom

Chinese (`zh-CN`) locale pages displayed English content. `<h1>` showed "Introduction" instead of "介绍".

## Root Cause

`render_doc_pages` content phase wrote to shared `pages[i].html`:

```cpp
pages[i].html = render_doc_body(md, rc.curLocale == "en");
```

With multi-locale parallel rendering, two threads overwrite each other:

```
Thread zh-CN: pages[i].html = Chinese content
Thread en:    pages[i].html = English content  ← overwrites zh-CN

Thread zh-CN: ctx.body = pages[i].html  ← reads English!
```

The old serial code ran zh-CN → en sequentially, so zh-CN wrote to disk before en overwrote. Parallel execution exposed the race.

## Fix

Replace shared `pages[i].html` with locale-local `bodyStore` array:

```cpp
std::vector<std::string> bodyStore(pages.size());
bodyStore[i] = toc.html;  // write locally
ctx.body = bodyStore[i];   // read locally
```

## Lesson

Shared mutable state must be audited when parallelizing. "Serial code works" ≠ "thread-safe code."
