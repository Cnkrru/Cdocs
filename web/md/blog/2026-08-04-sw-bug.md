## 现象

mermaid.min.js、katex.min.js、katex.min.css 在子目录页（`tests/test-mermaid.html`）始终 404。

## 排查过程

### 1. 疑点：路径拼接

错误日志显示请求路径为 `tests/assets/deps/katex.min.css`——子目录页的 JS 动态加载静态资源时，路径被错误地拼接了 `tests/` 前缀。

**尝试 1**：`util.js` 中用 `document.querySelector('link[rel="manifest"]')` 推导资产根路径 → 失败，`querySelector` 在 module 内返回 null。

**尝试 2**：用 `import.meta.url` 推导 → `import.meta.url` 返回的路径拼接出了双重 `assets/`（`/v2/zh-CN/assets/` + `assets/deps/...`）。

**尝试 3**：用 `<link rel="stylesheet" href="...style.css">` 推导 → 同样不可靠，模块加载时机早于 DOM ready。

**尝试 4（最终方案）**：C++ 构建期注入 `window.__cdocs_asset_root`。在 `map_render_page` 中计算 `relBase + "assets/"`，通过 Scripts 组件输出到 HTML：

```html
<script>window.__cdocs_asset_root="../assets/"</script>
```

JS 极简读取：`(window.__cdocs_asset_root || 'assets/') + rel`。不依赖 DOM、不依赖 `import.meta`。

### 2. 真凶：Service Worker

路径修复后仍 404。无痕模式正常——锁定 SW。

- 旧版 SW（`cdocs-v2`）缓存了旧 `util.js`（无 `assetPath` 修复）
- SW 生命周期特性：新 SW 只下载不激活，必须关闭所有本站标签页

**修复**：bump 缓存版本 `cdocs-v2` → `cdocs-v3`。

### 3. 连锁发现

排查过程还发现 ES 模块 `import` 语句不带 `?v=` 指纹，浏览器缓存旧的模块文件。**修复**：`fingerprint_js_imports` 扫描所有 JS 的 `import`/`export ... from` 语句，追加 `?v=hash`。

路径修复的另一半：`assets/js/features/pwa.js` 中注册 Service Worker 的 `./sw.js` 在子目录页会解成 `tests/sw.js` → 404。**修复**：改用 `new URL('./sw.js', ml.href)` 从 manifest 链接推导。

## 教训

1. **ES Module 的 `import` 没有 cache busting**：浏览器按 URL 缓存模块，文件改内容但 URL 不变 → 永远用旧版。必须在构建期给 `import` 语句追加 `?v=hash`。
2. **Service Worker 不是热更新的**：SW 独立于页面缓存，版本号 bump 只是"下次激活时生效"，用户需要关闭标签页或手动 Unregister。
3. **JS 模块内的路径推导不可靠**：`document.querySelector` 和 `import.meta.url` 在不同浏览器/时机下有不同表现。C++ 构建期注入是最可靠的方案。
